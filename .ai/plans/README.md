# Implementation Plans

Use this directory for implementation-ready plans for substantial, multi-step,
cross-cutting, architecturally meaningful, high-risk, hard-to-reverse, or
coordinated work. Tiny, obvious, low-risk changes do not need a plan.

Recommended filename:

`YYYY-MM-DD-short-task-name.md`

Plans must be grounded in the current repository, distinguish verified facts
from assumptions, identify exact files or areas, define concrete acceptance
criteria and validation, and carry an honest status.

Accepted statuses:

- Draft
- Approved
- In Progress
- Blocked
- Completed
- Superseded
- Abandoned

Update an active plan when its status, scope, approved approach, risks, edge
cases, acceptance criteria, validation, or outcome changes. Do not rewrite
history to make the original proposal appear correct. Record deviations and
changed assumptions honestly, link durable decisions when relevant, and retain
completed or superseded plans.

## Template

````md
# Plan: Task Name

## Status

Draft

## Objective

## Background

## Verified Facts

## Assumptions

## In Scope

## Out of Scope

## Proposed Approach

## Files or Areas Expected to Change

## Data, API, Schema, or External-State Impact

## Risks and Edge Cases

## Validation Plan

## Acceptance Criteria

## Handoff Notes
````
